\section{Overview}
Timer1 is the ATmega328P's 16-bit timer. Its output compare unit can toggle a pin and request an interrupt when the counter TCNT1 matches OCR1A, and its input capture unit copies TCNT1 into ICR1 when an edge arrives on the ICP1 pin. In this lab, three programs were written using these features: a 440~Hz rectangular wave with a selectable duty cycle, a ten-note scale played on a piezo speaker, and a square wave at half the frequency of a function generator's signal.

\section{Procedure}
\begin{itemize}

\item \textbf{Pre-lab Questions} The handout's questions were answered before writing Program 1:
\begin{enumerate}[label=(\alph*)]
  \item $f_{cc} = 16$~MHz.
  \item 1, 8, 64, 256, or 1024, selected with CS12:10 in TCCR1B.
  \item $f_{tc} = f_{cc} / sp$.
  \item $pw = 1/f_w = 1/440~\text{Hz} = 2.273$~ms.
  \item $\text{count} = f_{tc} \cdot pw$.
  \item $\text{count} = f_{cc} \cdot pw / sp$.
  \item Timer1 is 16 bits, so the max value is $2^{16} - 1 = 65535$.
  \item With $sp = 1$, $\text{count} = 16~\text{MHz} / 440~\text{Hz} = 36364 < 65536$, so $sp = 1$.
  \item $\text{count} = (16~\text{MHz}) \cdot (1/440~\text{Hz}) / 1 = 36363.6 \approx 36364$, which fits within our 16-bit register.
\end{enumerate}

\item \textbf{Program 1} The subroutine SETWAVE takes the period $pw$ in clicks (r25:r24), a duty cycle code (r23), and a prescaler code (r22). The high width is $pw$ shifted right 3, 2, or 1 times for 12.5\%, 25\%, or 50\%, and the low width is $pw$ minus the high width. For 75\% and 87.5\%, bit 7 of the code swaps the two widths.

Timer1 runs in CTC mode with OC1A set to toggle on each compare match. Each part lasts $\text{OCR1A} + 1$ clicks in CTC mode, so SETWAVE stores each width minus one.

On each compare match, the hardware toggles OC1A and clears TCNT1, and the ISR loads OCR1A with the width of the part that just started: LOWCNT (width of low) if PB1 is now low and HIGHCNT (width of high) if it is high.

\item \textbf{Program 2} The ten tone periods in Table~\ref{tab:tones} are copied from program memory into SRAM at startup. For each tone, the program calls SETWAVE at 50\% duty, waits 500~ms with waitnms from Lab~5, stops the timer by clearing TCCR1B, and waits another 500~ms.

\item \textbf{Program 3} Timer1 runs freely in normal mode at clk/8, so each click is 0.5~$\mu$s. CTC mode cannot be used because input capture and output compare share TCNT1. On each rising edge, the capture ISR stores ICR1 minus the previous capture in PERIOD. On each compare match, OC1A toggles and the compare ISR adds PERIOD to OCR1A, so the output toggles once per input period and has half the input frequency.
\end{itemize}

\begin{equation}
  D = \frac{t_{\text{on}}}{t_{\text{on}} + t_{\text{off}}}.
  \label{eq:duty}
\end{equation}

\section{Post-Lab}
\question{Program 1: Are the results what you expected? Can you see any deviation from what you expected? Why (or why not)?}
Yes. Each part of the wave is a whole number of timer clicks, and the hardware toggles OC1A at the compare match, so the ISR's response time does not affect the widths. The measured period of 2.280~ms is 0.32\% longer than the expected 2.273~ms. This most likely comes from the board's 16~MHz clock running slightly slow, since every width scales with it. The clock may be running slow because of temperature swings or the built-in tolerance. The measured duty cycles are within 0.4 percentage points of their targets.

\question{What are the limits of your program? What are the limits of the high and low portions of your signal? Why?}
\begin{itemize}
\item \textbf{Longest period.} The period $pw$ is stored in a 16-bit register, so the largest value is 65535 clicks. At $sp = 1$, that is 4.1~ms, or 244.1~Hz. Because SETWAVE treats $pw$ as unsigned, this is double the 32767 limit in the handout.
\item \textbf{Shortest high or low portion.} The ISR is the limit. After each toggle, the ISR has to load the next width into OCR1A before the timer counts past it, and it needs about 37 clock cycles to do that. If a portion is shorter than this, the timer passes the new value before it is loaded, misses the match, and keeps counting up to 65535 and around again, which adds a gap of up to 4.1~ms to the wave. At $sp = 1$, each portion should therefore be at least about 37 clicks (2.3~$\mu$s). For a 12.5\% wave, the short portion is $1/8$ of the period, so the period must be at least about $8 \times 37 \approx 300$ clicks, which limits the frequency to about 53~kHz.
\item \textbf{Longest high or low portion.} The longest single portion is the long part of a 12.5\% or 87.5\% wave.
\end{itemize}

\question{Program 2: What is the smallest and largest signal frequency that you can generate? Where are the limitations coming from?}
The smallest frequency is set by the 16-bit compare register. At $sp = 1$, it is $16~\text{MHz} / 65535 = 244.1$~Hz. A prescaler of 1024 would lower this to 0.238~Hz.

The largest frequency is limited by the ISR. It runs twice per period, once for each toggle, and takes about 37 clock cycles each time. If each half of the wave is shorter than that (above about 216~kHz), the ISR runs nonstop and the main program never runs.

\question{Program 3: Note the results and explain them.}
The output was 504.6~Hz, 0.28\% below the expected 506.0~Hz. Unlike Program 1, this result does not depend on the board's clock, because the input is measured and the output is generated with the same timer: the output always lasts exactly two input periods in clicks. This error is minimal and can be attributed to frequency drift in the generator or other factors.

\question{What is the longest period that you can measure with the last program?}
The capture ISR finds the period with a 16-bit subtraction (sub, then sbc). If the timer rolls over once between edges, the subtraction borrows, but because the arithmetic is modulo $2^{16}$, the result is still the correct period. This works as long as the timer rolls over at most once per period, so the longest measurable period is
\begin{equation}
  T_{max} = 65535 \times 0.5~\mu\text{s} = 32.77~\text{ms},
\end{equation}
which corresponds to an input of 30.5~Hz. With a prescaler of 1024, each click lasts $1024 / 16~\text{MHz} = 64~\mu\text{s}$, so the longest measurable period would be
\begin{equation}
  T_{max} = 65535 \times 64~\mu\text{s} = 4.19~\text{s}.
\end{equation}

\section{Discussion/Conclusion}
This lab used Timer1's output compare and input capture units to generate and measure waveforms in hardware. All three programs worked as designed. Program 1 produced all five duty cycles at 438.6~Hz, which is only 0.32\% below the target 440~Hz. Program 2 played the ten-note scale with the expected timing. Program 3 produced 504.6~Hz from a 1.012~kHz input and can measure periods of up to 32.77~ms.
